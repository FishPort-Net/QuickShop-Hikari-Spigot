This maintenance release improves virtual-account configuration and adds a reliable shop
transaction lifecycle API for policy integrations such as XConomyBank.

## Changes

- Moves per-account settings to `shop.virtual-accounts`, keeping unlimited money-flow overrides
  under each account's `unlimited-shop-money` section while placing account-specific insufficient
  funds and sign messages at the account root.
- Automatically migrates the previous virtual-account configuration layout without overwriting
  values already present in the new layout.
- Adds a shared transaction context with a unique transaction ID, persistent numeric shop ID,
  player-oriented trade direction, trader and owner identities, item quantities, currency, and
  `BigDecimal` price snapshots.
- Carries the same context through the cancellable pre-transaction event and the successful
  transaction event, and adds a terminal failure event for cancellation, insufficient funds,
  economy failure, item-transfer failure, and unexpected errors.
- Distinguishes configured shop-unit count from the actual number of individual items transferred,
  allowing quota integrations to handle stacked shops correctly.
- Treats an unavailable shop inventory as a failed item transaction so the economy transaction is
  rolled back instead of reporting a false success.
- Retains the existing purchase event constructors and getters for addon compatibility.
- Preserves Java 17 support for Ketting/Spigot 1.20.1 and the Java 21 modern Spigot platform build.
